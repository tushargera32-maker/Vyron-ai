# AETHER Database Schema (SQLite)

## 1. Goals & Conventions
- **Engine:** SQLite (local file) with WAL mode; **FTS5** for full-text search.
- **Access:** all reads/writes go through a repository layer; route handlers/services never embed raw SQL outside repositories/migrations.
- **Migrations:** versioned, forward-only migrations tracked in `schema_migrations`; include backup hooks before destructive migrations.
- **IDs:** text primary keys (UUID/ULID) generated by the app.
- **Timestamps:** ISO-8601 UTC text (`created_at`, `updated_at`) unless noted.
- **Soft delete:** `deleted_at` nullable where user-facing deletion/recovery or auditability is useful; hard-delete only via approved flows.
- **JSON columns:** stored as validated JSON text (Zod-typed in app) for flexible metadata/config blobs.
- **Foreign keys:** `PRAGMA foreign_keys = ON`.

## 9. Full-Text Search (FTS5)
Create FTS5 virtual tables (content-synced in app or via triggers, decided in implementation) for fast local search:
- `messages_fts(content, conversation_id UNINDEXED, message_id UNINDEXED)`
- `memories_fts(content, summary, memory_id UNINDEXED, project_id UNINDEXED, type UNINDEXED)`
- `document_chunks_fts(content, document_id UNINDEXED, chunk_id UNINDEXED, project_id UNINDEXED)`

**Notes:** maintain sync on insert/update/delete/approval-state changes as applicable; filter by project/status in queries.

## 10. Migrations (applied)
1. `001_initial` — baseline schema: core tables, knowledge/memory/agent/learning/usage/audit, and FTS5 (`messages_fts`, `memories_fts`, `document_chunks_fts`).
2. `002_phase3` — Phase 3 extensions: `conversations.deleted_at` (+ index), `chunk_embeddings`, `memory_retrieval_events`.
3. `003_local_user_init` — idempotent local single-user profile initialization (`local_profile` with `local-user` row).

This schema is a baseline; evolve via forward-only migrations with tests and approval for major structural changes.
